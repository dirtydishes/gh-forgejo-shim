## Accepted findings, by severity

Highest severity:
1. `/branch_protections` is admin-only (`routers/api/v1/api.go:864-872`). For any non-admin, `baseRef`, `reviewDecision`, `mergeStateStatus` and `isRequired` return FORBIDDEN, which breaks `gh pr status`, `gh pr merge` and `gh pr checks`. The e2e oracle runs as admin, so it never saw this. (Sol)
2. `status_check_contexts` can be JSON null (`routers/api/v1/repo/branch.go:680`, `services/convert/convert.go:171`). Deserialization fails for any rule created without contexts. (Luna)
3. Team review requests have `user: null` (`models/issues/review.go:175-189`, `services/convert/user.go:16`). The whole review list fails to parse. (Luna)
4. gh asks for `baseRef.branchProtectionRule.requiredApprovingReviewCount` on the current-PR path of `gh pr status` (gh `pkg/cmd/pr/status/http.go:96`). The field doesn't exist, so the query fails validation. (Sol)

High:
5. Review decision differs from Forgejo (`models/issues/pull.go:901-952`). Forgejo counts only `official` approvals and rejections; stale approvals are skipped only under `ignore_stale_approvals`; outstanding official review requests block under `block_on_official_review_requests`. (Opus, Sol)
6. Status checks enabled with no valid contexts: Forgejo requires the combined status of all checks to be success, and "no statuses" blocks (`services/pull/commit_status.go:65-77`). We said the PR was mergeable. (Sol)
7. Deleted head branch: Forgejo reports `head.ref = refs/pull/N/head` (`services/convert/pull.go:102-106,210-226`). `headRefName` and branch lookups break. (Opus)
8. Auto-merge with an expected head races between our GET and Forgejo's schedule, and Forgejo never binds the schedule to a SHA (`routers/api/v1/repo/pull.go:993-1009`). (Sol)
9. Auto-merge with a merge style the repo disables is accepted, then silently dropped by the worker (`services/automerge/automerge.go:227`, `services/pull/merge.go:239-247`). (Sol)

Medium:
10. A required `warning` status reads as success; Forgejo blocks it (`modules/structs/commit_status.go:55`). (Sol)
11. Cancelled Actions jobs show as failures; blocked jobs show as in progress (`services/actions/commit_status.go:95-104`). This changes gh's exit code. (Opus, Sol)
12. Under a subpath install, Actions jobs aren't recognized as check runs (`models/repo/repo.go:598`). (Opus, Sol)
13. Workflow discovery skips `.gitea/workflows` and falls through past an existing but empty `.forgejo/workflows` (`modules/actions/workflows.go:62-102`). (Opus)
14. A 412 refusal (closing a PR that has open dependencies, editing a merged PR) is reported as INTERNAL (`routers/api/v1/repo/pull.go:738,747`). (Sol)
15. PR create sends `allow_maintainer_edit`, which Forgejo ignores (`modules/structs/pull.go:80`), so fork PRs never allow maintainer edits. (Luna, Sol)
16. Mark-ready strips every WIP prefix in a loop, deleting user title text. (Sol)
17. Search drops quote marks, so phrases become loose keywords. (Sol)

Low (fixed as they're nearly free): PRs sorted by timestamp string instead of number; null timeline elements.

## Fixes
forgejo-github-api PR #6 fixed findings 1-17 and the low items, each with a test. Three rounds of Sol review followed. Each one led to further fixes:
- non-admins see `protected` with no rule name, so rules hidden from them yield `UNKNOWN`/null;
- repo-scoped tokens fall back to the branch summary;
- auto-merge refuses an expected head, merges a ready PR at once, and retries once after a base race;
- `warning` maps to FAILURE.

The non-admin path is covered by fixtures; the e2e user is an admin.

## Known limits, not fixed
- `autoMergeRequest` comes from timeline history plus the repo's default merge style. Forgejo exposes no read API for the scheduler row, so a worker-failed schedule still looks enabled. (Sol #8)
- PR search intersects with the full PR list. That's cheaper than per-PR reads for normal repos; it fails only past 10,000 PRs in one state. (Sol #12, downgraded)
- Check-run durations are zero: commit statuses carry one timestamp. (Sol #16)
- ~~An unknown Actions run status fails the whole runs list instead of inventing a state. Forgejo never stores `unknown`, and the test deliberately pins the refusal.~~ Changed since: Forgejo gives a run with no jobs `unknown` and counts it as pending, so the gateway reports it as `queued` (DESIGN.md's runs row). Other unrecognised states still fail.
- Workflow discovery is not recursive; Forgejo lists subdirectories too (`modules/actions/workflows.go:91`).
- `gh run list --workflow` has no `/actions/workflows/{id}/runs` route.
- `mergeable` never reports CONFLICTING, because Forgejo's `mergeable=false` also covers "checking" and WIP (`models/issues/pull.go:882`).

## Rejected leads
- Luna rows 4/15/21/22: "the converter returns null on a load error". That's a Forgejo internal error, and we already surface it as an upstream error.
- Luna row 19: `exclude_pull_requests` only omits GitHub's `pull_requests` array, which we never send. Ignoring it is correct.
- Luna dead-code top items: speculative trims of the gh-pinned schema.
