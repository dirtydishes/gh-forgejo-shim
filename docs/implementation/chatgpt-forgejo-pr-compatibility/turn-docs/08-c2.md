## Changed Behavior And Files

- Added private `src/auth_config.rs` and moved credential-file parsing plus its focused tests out of `auth.rs`. JSON and text records now share one rule: a token is eligible only when every stated host field is a valid match; a matching JSON map key may supply the host only when no stated field conflicts.
- `auth.rs` is now 883 lines, below the required 1,000-line boundary.
- Paginated PR discovery now validates the raw success body as an array containing only objects. A non-array or mixed page returns `Forgejo API returned an invalid pull request page` before pagination or stdout.
- The legacy and paginated pull-list paths now call the same head predicate. `forgejo.rs` is 975 lines.
- Credential JSON is now parsed by a duplicate-key-rejecting visitor inside `auth_config.rs`. This keeps every explicit host occurrence available to the shared record policy instead of letting normal map construction overwrite earlier evidence.
- JSON record/container classification is authoritative: any object with a recognized host or token field is one record, while a field-free map accepts one normalized-matching host key, recurses on zero, and fails closed on more than one.
