## Discoveries And Decisions

- The accepted report contains one exact captured argv: the Dirtypages `pr list` command. It gives exact `pr view` fields and exact no-check output, but only templates for version, auth, view, and checks.
- A read-only Lavender check reached the cited build-6720 log. The log confirms the loopback GraphQL failure and old-`gh` checks failure, but it does not record full `gh` argv.
- Lavender now has ChatGPT build 6962, not 6720. Read-only inspection of its packaged command builders confirms the same core command order, the same 25 view fields, and the full checks field list. The fixture records that as supplemental current-source confirmation, not as a build-6720 capture.
- No fresh trace mismatch was found. Values absent from both the accepted report and current packaged source remain unstated rather than inferred.
- The first independent review rejected the hand-written GitHub view sample because it did not prove the literal 25-field result and incorrectly showed an empty `commits` array. The repair uses the official GitHub CLI 2.96.0 release binary against a real public PR, keeps its complete output as a redacted fixture, and records the verified release archive SHA-256.
- A process-level fake Forgejo server under the legacy host list would require either trusted test TLS on port 443 or a product-only test escape hatch. Neither belongs in S1. The `@me` probe instead uses S2's accepted profile CLI and `api_root` contract to run the exact managed-`gh` list argv against a local HTTP server. It observes both `GET /user` and pull-list requests and can turn green through the accepted S2-S6 path. Missing-field and checks probes use the current public normalization seams, while alias routing stays at the managed-`gh` process seam.
