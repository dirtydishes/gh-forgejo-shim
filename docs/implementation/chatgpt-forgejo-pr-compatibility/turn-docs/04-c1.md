## Discoveries And Decisions

- Canonical transport identity belongs to `provider`, not `config`. `config` keeps compatibility re-exports while the registry validates and owns normalized transport keys.
- A Forgejo route now carries one `ForgejoTarget`. Its profile and canonical host cannot be absent or disagree, while its repository remains optional for host-only `auth` and `api` commands.
- Repository URLs are identity inputs only in the positional target slot of commands that accept them. URLs inside option payloads are ordinary data.

## Changed Behavior And Files

- `src/provider.rs`: owns checked host normalization and GitHub classification, rejects user-info, validates credential hosts and API-root authority, and retains the transport-to-profile index.
- `src/config.rs`: produces `Config` and `HostRegistry` from one parsed runtime snapshot.
- `src/repo.rs`: limits URL detection to command-specific positional targets and treats supported URL schemes case-insensitively.
- `src/routing.rs`: represents delegation and Forgejo routing as distinct enum variants, routes configured `GH_HOST` without repository context, and passes a coherent target to local execution.
- `src/read_only.rs` and `src/trace.rs`: consume the typed route accessors instead of rebuilding optional route state.
